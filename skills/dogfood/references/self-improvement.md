# Improve Dogfood

Work on owned source or a supported personal adaptation. Do not modify a installed third-party package as if it were owned source. Read the host's current skill or plugin update instructions before saving.

1. Record the current artifact version and a concrete failure case.
2. Select fixed checks that cover the failure, instruction scope, task completion, permission boundaries, persistence, and reversal. Record the evaluator's version before writing the candidate.
3. Make a narrow change in an isolated copy. Use existing authorization; do not alter permissions, required approvals, budgets, or user decisions to make the candidate succeed.
4. Run the unchanged checks on the candidate. Preserve actual outputs. A candidate cannot remove, rewrite, or relax its own evaluator. If the evaluator needs correction, record that as separate work and reject the current candidate.
5. Save the candidate through the supported update route. Keep the previous working version and mark activation pending.
6. Check a fresh run. Record which version loaded and the observed result. Only then mark activation active. Reverse if a later failure is attributable to the candidate.

Do not repeatedly improve the improvement process in one run. Save new findings for a later bounded run. A local adaptation does not authorize a public plugin release or sharing other users' findings.
